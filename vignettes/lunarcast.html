Get started with lunarcast

lunarcast forecasts monthly and quarterly series that react to moving holidays: holidays such as Eid al-Fitr, Eid al-Adha, the Chinese New Year or Easter, whose Gregorian date changes every year. This vignette walks through a complete analysis. The method is explained in vignette("theory") and compared with the classical calendar variation model in vignette("classic-vs-lunarcast").

Installation

# install.packages("pak")
pak::pak("novrisuhermi/lunarcast")

# or, with vignettes
# install.packages("remotes")
remotes::install_github("novrisuhermi/lunarcast", build_vignettes = TRUE)

The data

The package contains sapi, the monthly Google Trends index for “sapi” (cattle) in Indonesia. Interest peaks before Eid al-Adha, when cattle are bought for the sacrifice.

library(lunarcast)
plot(sapi, xlab = "", ylab = "Google Trends index",
     main = "Search interest in \"sapi\"")

Two features make this series hard: the peaks move to an earlier month every few years, and their size changes, from almost nothing in 2004 to more than three times the usual level in the late 2010s.

Step 1: holiday dates

adha <- holiday_dates("idul_adha")
tail(adha, 4)
#> [1] "2024-06-17" "2025-06-06" "2026-05-27" "2027-05-17"

holiday_dates() gives the Indonesian dates of Eid al-Adha, Eid al-Fitr and the Chinese New Year from 2004 to 2027, and easter_dates() computes Easter and the holidays that follow from it. Any other holiday is simply a vector of dates.

easter_dates(2025:2026, offset = -2)   # Good Friday
#> [1] "2025-04-18" "2026-04-03"
my_holiday <- as.Date(c("2024-03-11", "2025-03-29", "2026-03-19"))

Step 2: from dates to regressors

A holiday influences the days around it, not a calendar month. holiday_window() computes the share of a window of days around each occurrence that falls in each month.

w <- holiday_window(adha, window = c(-3, 7), y = sapi)
window(w, start = c(2020, 6), end = c(2020, 9))
#>            Jun       Jul       Aug       Sep
#> 2020 0.0000000 0.3636364 0.6363636 0.0000000

Eid al-Adha fell on 31 July 2020. The window from three days before to seven days after puts 36% of the holiday in July and 64% in August, where the searches indeed peaked. A monthly dummy would have put everything in July. You do not need to build these regressors yourself; lunarcast() does it and chooses the window.

How to read the output:

  • The first line is the fitted regression with ARIMA errors and its AICc.
  • Structure is the selected trend and seasonal structure. The trend type comes from KPSS tests; the table below it lists the candidate seasonal structures with their cross-validated RMSE and its standard error. The default one-SE rule takes the simplest structure within one standard error of the best.
  • For each holiday you see whether its effect is constant or two-level, the selected window in days around the holiday and, for two-level effects, the level-2 rule used to forecast the next effect.
  • ratio is the multiplicative effect eαe^{\alpha}eα: 2.5 means that the holiday (when its whole window falls in one month) multiplies the level of that month by 2.5.

Scenarios

To ask “what if the next Eid al-Adha doubles the level?”, fix its effect:

sc <- forecast(fit, h = 13, level2 = list(adha = log(2)))
round(cbind(model = fc$mean, scenario = sc$mean)[5:7, ], 1)
#>      model scenario
#> [1,]  20.4     20.4
#> [2,]  45.3     37.6
#> [3,]  29.9     27.1

Taking control of the automatic choices

Every automatic choice can be fixed, which also makes fitting much faster.

Argument What it controls Example
window days around each holiday window = list(adha = c(-3, 7), fitri = c(-28, 3))
effect constant or two-level effect effect = list(adha = "two-level", fitri = "constant")
trend, season trend and seasonal structure trend = "stochastic", season = "none"; trend = "cv" compares both trend types
select how the structure is chosen select = "aicc"
cv_rule, cv_years cross-validation rule and origins cv_rule = "min", cv_years = 3
level2 rule for future effects level2 = list(adha = "rw")
outliers detect AO, LS and TC outliers outliers = TRUE
lambda transformation (0 = log) lambda = NULL for additive effects 
fast <- lunarcast(sapi, hol,
                  window = list(adha = c(-3, 7), fitri = c(-28, 3)),

The classical model

The classical calendar variation model, with a dummy for the holiday month and the same effect every year, is available in the six structures m1 to m6:

m6 <- calvar_classic(sapi, adha, trend = "stochastic", season = "stochastic")
m6
#> Classical calendar variation model: stochastic trend + stochastic seasonality 
#> Regression with ARIMA(1,1,1)(1,0,2)[12] errors | AICc = 1708.9 
#> Holiday effect (same every year): 18.92 (s.e. 2.01), original scale

calvar_classic_all() fits all six at once, and forecast() works for both kinds of models. The two approaches are compared in vignette("classic-vs-lunarcast").

Evaluating forecasts

rolling_origin() refits models at the end of every year and forecasts the next year; rolling_summary() reports the RMSE overall, in holiday months, in years in which the holiday moved to another month, and the median of the yearly RMSEs.

models <- list(
  classic_m6 = function(y, h)
    forecast(calvar_classic(y, adha, "stochastic", "stochastic"), h = h)$mean,
  lunarcast  = function(y, h) forecast(lunarcast(y, hol), h = h)$mean
)
r <- rolling_origin(sapi, adha, models, first = 2012)
rolling_summary(r)

forecast_accuracy() gives RMSE, MAE, MAPE and sMAPE for a single test period.
