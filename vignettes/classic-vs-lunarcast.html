From the classical model to lunarcast

This vignette reproduces the classical analysis of the sapi series (six trend and seasonal structures crossed with three calendar designs, 18 models fitted to 2004–2024 and tested on 2025), adds lunarcast to it, and then shows why a single test year is not enough to compare them.

library(lunarcast)
adha  <- holiday_dates("idul_adha")
fitri <- holiday_dates("idul_fitri")
train <- window(sapi, end = c(2024, 12))
test  <- window(sapi, start = c(2025, 1))

Six structures and three calendar designs

Each model is a regression with ARIMA errors on the original scale, so the holiday effects are additive and the same in every year. The six structures combine a trend and a seasonal component:

Model Trend Seasonality
m1 deterministic (β0+β1t\beta_0 + \beta_1 tβ0​+β1​t) 11 monthly dummies
m2 deterministic Fourier terms, K=5K = 5K=5
m3 stochastic (differencing) 11 monthly dummies
m4 stochastic Fourier terms, K=5K = 5K=5
m5 deterministic seasonal ARIMA
m6 stochastic seasonal ARIMA

The calendar part CtC_tCt​ has three designs:

Design design Calendar part CtC_tCt​
D1, month dummy "dummy" αVt\alpha V_tαVt​, with Vt=1V_t = 1Vt​=1 if month ttt contains Eid al-Adha
D2, lead–lag dummies "leadlag" α−1Vt+1+α0Vt+α+1Vt−1\alpha_{-1} V_{t+1} + \alpha_0 V_t + \alpha_{+1} V_{t-1}α−1​Vt+1​+α0​Vt​+α+1​Vt−1​
D3, proportional windows "window" αbefore PREt(w)+αholiday HOLt\alpha_{\text{before}}\,\mathrm{PRE}_t(w) + \alpha_{\text{holiday}}\,\mathrm{HOL}_tαbefore​PREt​(w)+αholiday​HOLt​

In D3, PREt(w)\mathrm{PRE}_t(w)PREt​(w) is the share of the www days before Eid al-Adha that falls in month ttt and HOLt\mathrm{HOL}_tHOLt​ the share of the holiday and the three tasyrik days (Bell and Hillmer, 1983). The window length www is chosen from 7, 14, 21 and 28 days: every structure ranks the four by AICc, and the length chosen by most structures is used for all six.

Five of the six structures prefer w=14w = 14w=14 days. Within every structure the proportional windows give the smallest AICc of the three designs (for m6, 1593.2 against 1647.5 with the month dummy). The effect of the two weeks before the holiday is small (about 6 index points for a full window) but the holiday window carries 21 to 26 points, and it is spread correctly over two months when Eid al-Adha falls at the end of a month. The lead–lag dummies show the same thing more crudely: the months before and after the holiday month have small positive effects. With seasonal ARIMA errors (m5, m6) part of the holiday effect is carried by the seasonal autoregression, so the estimated effects are smaller than in m1 to m4.

A single test year is a fragile basis for comparison. In 2025 Eid al-Adha fell in June for the third year in a row, the ideal situation for a seasonal ARIMA model, which simply repeats last year’s June, so the classical m6 model with the month dummy also does well, even better than with proportional windows. The difficult years are those in which the holiday moves to another month, and they do not occur every year.

Fourteen test years: rolling origin

rolling_origin() refits every model at the end of each year from 2011 to 2024 and forecasts the following year, so that 14 test years (2012 to 2025, 167 months) are used. With proportional windows, the length of the window before the holiday is chosen again by AICc at every origin. Running it for all models takes some time; the results for sapi are stored in the package:

The lunarcast rows differ only in how the seasonal structure is chosen: by AICc (lunarcast_aicc), fixed without seasonality (lunarcast_none) or by cross-validation with the one-standard-error rule (lunarcast, the default). lunarcast_split gives Eid al-Adha the two windows of the classical window design, the 14 days before the holiday and the holiday with the tasyrik days, each with its own effect. What the table shows:

  • Proportional windows improve every classical structure. The best classical model is now m6 with proportional windows, with an RMSE of 7.30 instead of 7.95 for the month dummy. Lead–lag dummies hardly help (8.05 for m6).
  • The gain stays small in the months that matter: in holiday months the RMSE of m6 falls only from 20.25 to 19.66, because the effect is still the same in every year. lunarcast lowers the overall RMSE to 4.94 and the RMSE in holiday months to 8.30.
  • The two classical windows do not help inside lunarcast either: lunarcast_split has an RMSE of 7.76, against 4.94 for the single window that lunarcast chooses by AICc, (−3,+7)(-3, +7)(−3,+7), which also covers the week after the holiday. The option is there to reproduce a chosen window design, not as a better default.
  • Choosing the structure by AICc picks seasonal ARIMA errors at most origins and gives a clearly worse forecast than cross-validation: a good in-sample fit is not the same as a good forecast.

How the rolling-origin results were produced

hol  <- list(adha = adha, fitri = fitri)
spec <- classic$spec[classic$spec$design == "dummy", ]
classic_design <- function(design, suffix) {
  m <- lapply(seq_len(6), function(i) {
    force(i)
    function(y, h) forecast(calvar_classic(y, adha, spec$trend[i], spec$season[i],
                                           design = design), h = h)$mean
  })
  setNames(m, paste0("classic_m", 1:6, suffix))
}
classic_models <- c(classic_design("dummy", ""),
                    classic_design("leadlag", "_leadlag"),
                    classic_design("window", "_window"))

# the lunarcast variants share the calendar selected at each origin
lunarcast_variant <- function(...) {
  function(y, h) {
    base <- lunarcast(y, hol, select = "aicc")
    fit  <- lunarcast(y, hol, window = base$window, effect = base$effect, ...)
    forecast(fit, h = h)$mean
  }
}
lunarcast_models <- list(
  lunarcast_aicc  = function(y, h) forecast(lunarcast(y, hol, select = "aicc"), h = h)$mean,
  lunarcast_none  = lunarcast_variant(season = "none", select = "aicc"),
  lunarcast       = lunarcast_variant(),
  lunarcast_split = function(y, h)
    forecast(lunarcast(y, hol, window = list(adha = list(before = c(-14, -1),
                                                        holiday = c(0, 3)))),
             h = h)$mean
)
r <- rolling_origin(sapi, adha, c(classic_models, lunarcast_models), first = 2012)
rolling_summary(r)
